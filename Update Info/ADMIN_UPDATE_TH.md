# TRIGEAR — Admin Dashboard และบล็อกสมาชิก

ใช้ ZIP TRIGear (4) ของคุณเป็นฐาน และเก็บฐานข้อมูล สินค้า สมาชิก รูปภาพ และไฟล์ประกอบเดิมไว้

## เริ่มใช้งาน
1. ปิดโปรแกรมเดิมก่อน และเก็บโฟลเดอร์เดิมเป็นสำรอง
2. แตก ZIP นี้เป็นโฟลเดอร์ใหม่ เปิดโฟลเดอร์ TRIGear
3. หากยังไม่ติดตั้ง dependencies: `py -m pip install -r requirements.txt`
4. เปิดด้วย `py main.py` หรือ START_TRIGEAR.bat แล้วล็อกอิน Admin เดิม
5. ครั้งแรกโปรแกรมเพิ่มคอลัมน์สถานะบล็อกและตารางประวัติโดยอัตโนมัติ สมาชิกเดิมทุกคนยังใช้งานได้

ข้อมูลใน ZIP เป็นสำเนาจากไฟล์ที่ส่งมารอบนี้ หากนำไปใช้หลังจากร้านมีการเพิ่มข้อมูลอีก ต้องย้าย database/shop.db, uploads, assets, picture catalog และ config ล่าสุดจากเครื่องร้านมาทั้งชุดก่อนเปิด ห้ามนำ DB ใน ZIP ทับข้อมูลใหม่ของร้าน

## หน้า Dashboard
- แถบเมนูซ้ายและสีตามภาพตัวอย่าง พื้นที่รายงานเลื่อนด้วยล้อเมาส์ได้
- การ์ดสินค้า คำสั่งซื้อ ลูกค้า เป็นจำนวนทั้งหมด; การ์ดรับชำระและรับชำระหักคืนเงินอิงช่วงรายงาน
- วันนี้ / เดือนนี้ / ปีนี้ เป็นช่วงตั้งแต่ต้นวัน/เดือน/ปีถึงวันนี้; ปฏิทินเลือกวันเริ่มและวันสิ้นสุด จากนั้นกดแสดง
- กราฟ: ยอดรับชำระรวม VAT และยอดคืนเงินจริง หรือจำนวนออเดอร์ทั้งหมดที่สร้าง เลื่อนเมาส์บนกราฟเพื่อดูค่า
- ช่วงไม่เกิน 62 วันใช้รายวัน, ไม่เกิน 1,096 วันใช้รายเดือน, มากกว่านั้นใช้รายปี
- เลือกได้สูงสุด 10 ปีต่อรายงาน
- สถานะคำสั่งซื้ออิงวันสร้างออเดอร์ กดปุ่มสถานะแล้วเลือกรายการเพื่อเปิดจัดการได้
- สินค้าขายดีมีช่วงวันที่ของตัวเอง เลือกเรียงตามจำนวนชิ้นหรือมูลค่าก่อน VAT และกรองหมวดหมู่ได้
- รวมไซส์เป็นสินค้าเดียวกัน; การกรองหมวดใช้หมวดที่ผูกกับสินค้านั้นโดยตรง
- การล้างตัวกรองสินค้าขายดีจะกลับเป็นเดือนนี้ สินค้าทั้งหมด เรียงจำนวนชิ้น

## หลักการนับเงิน
ยอดรับชำระนับเฉพาะ orders.payment_status = ชำระเงินแล้ว ตามวันสร้างออเดอร์ (ระบบเดิมยังไม่มีวันที่ Admin อนุมัติการชำระแยกไว้) ไม่ใช่รายงานกระแสเงินสดตามวันรับเงินจริง
VAT ใช้ค่าที่บันทึกไว้ในออเดอร์เดิม ไม่บวกย้อนหลัง ออเดอร์เก่าที่ไม่มี VAT ยังคงยอดเดิม
ยอดคืนเงินนับเฉพาะคืนเงินสำเร็จตาม refund_date ในช่วงวันที่เลือก จึงอาจรวมเงินคืนของออเดอร์จากเดือนก่อน
ยอดรับชำระหักคืนเงิน = ยอดรับชำระในช่วง − เงินคืนจริงในช่วง จึงอาจติดลบได้ และไม่ใช่กำไร
คำสั่งซื้อยกเลิกที่เคยชำระยังอยู่ในยอดรับชำระและถูกหักเมื่อคืนเงินจริง แต่สินค้าขายดีตัดออเดอร์ยกเลิก/รอคืนเงิน/คืนแล้วออกทั้งหมด
วันที่แบบ CURRENT_TIMESTAMP ใน DB เป็น UTC จึงแสดงสถิติตามเวลาไทย +7; วันที่ ISO แบบเดิมของแอปเป็นเวลาท้องถิ่น

## บล็อกสมาชิก
หน้าจัดการสมาชิก > เลือกลูกค้า > บล็อกลูกค้า / ปลดบล็อก > ระบุเหตุผล
บล็อกได้เฉพาะลูกค้า ไม่บล็อก Admin; บัญชีที่ถูกบล็อกจะเข้าสู่ระบบไม่ได้ และมอบ Role Admin ไม่ได้จนกว่าจะปลดบล็อก
โปรแกรมตรวจบัญชีที่ล็อกอินทุก 1 วินาที และตรวจอีกครั้งภายใน transaction สร้างออเดอร์
ประวัติบล็อกและปลดบล็อกแสดงในรายละเอียดสมาชิก เก็บผู้ดำเนินการ เวลา และเหตุผลไว้ให้ Admin
ไม่ลบตะกร้า โปรไฟล์ ที่อยู่ ออเดอร์ หรือยกเลิกคำสั่งซื้อเดิมอัตโนมัติ Admin ยังจัดส่งและคืนเงินได้ตามขั้นตอนเดิม

## การตรวจสอบ
`py tests/test_admin_dashboard.py` ทดสอบกับฐานข้อมูลชั่วคราว ไม่แตะฐานข้อมูลร้าน
ทดสอบยอดขาย VAT คืนเงิน อันดับสินค้า หมวดหมู่ สิทธิ์บล็อก/ปลดบล็อก ล็อกอินบัญชีบล็อก session ที่เปิดอยู่ และ migration ซ้ำ
ตรวจการย้าย schema บนสำเนาฐานข้อมูลจริงแล้ว ทุกแถวและคอลัมน์เดิมคงเดิม
ตรวจ syntax ผ่าน; ยังไม่ได้เปิดตรวจ UI บน Windows จริงในสภาพแวดล้อมที่พัฒนา กรุณาตรวจความพอดีของข้อความบนจอเครื่องร้าน
ไม่ได้ส่งอีเมลหรือเชื่อมต่อกล้องจริงระหว่างทดสอบ

ไฟล์สภาพแวดล้อม .venv และแคช Python ไม่รวมในชุดส่งมอบ ให้ติดตั้ง dependencies บนเครื่องที่ใช้งาน

## อีเมล OTP รูปแบบใหม่
ใช้การ์ดพื้นขาว โลโก้ TRIGEAR และรหัสสีม่วงน้ำเงินขนาดใหญ่ที่คัดลอกได้
แยกหัวข้อสมัครสมาชิกกับตั้งรหัสผ่านใหม่ ระบุอายุ 10 นาที ใช้ครั้งเดียว และคำเตือนห้ามเปิดเผยรหัส
รองรับ HTML และข้อความธรรมดาสำรอง; โลโก้แนบภายในอีเมล ไม่ต้องโหลดจากเว็บภายนอก
หากโปรแกรมเมลซ่อนภาพ ยังแสดงชื่อร้านและรหัสได้ครบ
ทดสอบด้วย `py tests/test_otp_email.py` โดยจำลอง SMTP ไม่ส่งอีเมลจริง
